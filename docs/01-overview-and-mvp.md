# Puck Terminal 设计开发文档：总览与 MVP

## 1. 产品定位

Puck Terminal 是一个基于 Tauri 的桌面终端模拟器，面向需要同时管理本地终端、远程服务器、文件传输与多语言界面的开发者和运维用户。首版目标不是复制完整的 IDE，而是提供一个稳定、清晰、可扩展的终端工作台。

参考产品方向：

- Otty：现代原生终端、多会话、清爽交互、主题化体验。
- iTerm2 / Windows Terminal：本地 shell、多标签、主题、快捷键。
- Termius / FileZilla：远程连接配置、SSH 与文件传输工作流。

## 2. 首要目标

首版需要实现并围绕以下能力设计：

- 本地终端模拟：支持启动系统 shell，并识别 WSL、zsh、bash 等可用环境。
- SSH 终端：支持保存连接配置、打开远程交互式 shell。
- SFTP / FTP / FTPS：支持远程文件浏览、上传、下载、重命名、删除与传输队列。
- 前端技术：React + shadcn/ui + xterm.js。
- Tauri 能力：通过 Rust 后端处理 PTY、网络连接、文件传输、凭据存储与系统能力。
- 多语言：至少预留中文、英文语言包结构。
- 主题系统：支持亮色、暗色、跟随系统，以及多套终端配色主题。

## 3. MVP 范围

MVP 必须交付一个可用的“终端 + 连接 + 文件传输”工作台：

| 模块 | MVP 要求 |
| --- | --- |
| 本地终端 | 启动默认 shell，支持 zsh/bash，Windows 下支持 PowerShell/cmd/WSL 检测 |
| SSH | 新建连接、保存连接、密码/密钥认证、打开远程 shell |
| SFTP | 基于 SSH 连接打开文件管理器，上传/下载文件 |
| FTP/FTPS | 新建 FTP/FTPS 连接，浏览目录，上传/下载文件 |
| 会话 | 支持多标签，会话断开提示，手动重连 |
| 主题 | 应用主题 + 终端配色主题分离 |
| 多语言 | UI 文案使用 i18n key，不在组件中硬编码主要文案 |
| 凭据 | 连接配置本地保存，密码与私钥口令进入系统钥匙串 |

## 4. 非目标

以下能力不进入首版实现，但文档需要为后续扩展保留边界：

- 云同步账号体系。
- 团队共享连接。
- AI agent 工作流。
- 远程端自动安装 agent。
- 复杂脚本编排、宏录制、任务流水线。
- 全量 IDE 功能，例如代码索引、调试器、语言服务。
- 移动端适配。

## 5. 核心用户流程

### 5.1 打开本地终端

1. 用户进入应用。
2. 应用检测可用 shell。
3. 默认打开一个本地终端标签。
4. 用户可以新建 zsh、bash、PowerShell、cmd 或 WSL 会话。

### 5.2 打开 SSH 连接

1. 用户创建 SSH 连接配置。
2. 输入 host、port、username、认证方式。
3. 密码或私钥口令保存到系统钥匙串。
4. 连接成功后打开 xterm.js 终端会话。
5. 断线后展示状态，并允许手动重连。

### 5.3 使用文件传输

1. 用户从连接列表打开 SFTP、FTP 或 FTPS。
2. 应用展示文件管理器视图。
3. 用户浏览目录、上传、下载、删除、重命名。
4. 传输任务进入队列，展示进度、成功、失败与重试。

## 6. 术语

| 术语 | 定义 |
| --- | --- |
| Session | 一个正在运行或曾经运行的终端/文件连接实例 |
| Profile | 可复用的连接配置，包括协议、主机、端口、用户名、默认目录等 |
| Credential | 密码、私钥口令等敏感信息，只允许存入系统安全存储 |
| Terminal Pane | 承载 xterm.js 实例的终端区域 |
| Transfer Queue | 文件上传下载任务队列 |
| Theme | 应用 UI 主题与终端配色主题的组合 |

## 7. 成功标准

首版被认为可用，需要满足：

- 可以稳定打开本地 shell，并完成基础交互命令。
- 可以成功连接常见 SSH 服务器。
- 可以通过 SFTP、FTP、FTPS 浏览目录并传输文件。
- 多标签不会互相串流或污染状态。
- 主题切换不会导致终端不可读。
- 中英文切换不需要重启应用。
- 敏感凭据不明文落入普通配置文件。
